# AlgoResearch AI

A focused prototype for turning a natural-language trading question into a structured, reviewable research experiment.

## User flow

`Question -> Understand -> Clarify -> Define -> Test -> Learn`

The prototype intentionally stops short of live data, brokerage actions, and financial advice. It demonstrates ambiguity handling: the assistant extracts what was provided, surfaces what is missing, and waits for the user before choosing material parameters.

## Architecture

```text
Browser (Next.js client)
  |-- POST /api/research/analyze -> structured parser + Zod validation
  |-- POST /api/research/test    -> deterministic backtest engine
  `-- Results UI                -> Recharts chart + data/interpretation sections

Simulated NIFTY OHLC data -> strategy loop -> metrics
```

## Technologies

- Next.js App Router and React for the workspace and server routes.
- TypeScript for experiment, trade, and result contracts.
- Tailwind CSS v4 for layout with a small global visual system.
- Zod for runtime validation at API boundaries.
- Recharts for the strategy versus benchmark chart.

The analysis route uses a deterministic parser so the assignment can be demoed without an API key. It is isolated behind the same structured contract an LLM would return; a production version can replace that function with a server-side LLM adapter and retain the Zod boundary.

## Backtesting

`data/nifty-sample.ts` contains simulated daily OHLC observations. The engine detects a previous-day decline, optionally applies the high-volatility filter, enters at the next open, holds for the selected number of trading days, and exits at the close. It calculates trade count, winners, losers, win rate, average/median/best/worst trade, strategy return, and a benchmark series.

Results are calculated by code. No numerical result is generated by AI.

## Local setup

```bash
npm install
npm run dev
```

Open `http://localhost:3000`. Run `npm run build` for a production check.

## Key decisions

- Missing holding periods and phrases such as `sharp fall` trigger clarification instead of silent defaults.
- The final experiment labels the simulated dataset and no-cost assumption visibly.
- The UI separates calculated facts, interpretation, and limitations.
- The result engine is deterministic so repeating an experiment gives the same result.
